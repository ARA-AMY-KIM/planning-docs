1. 개요

왜 바꾸는가

1.1 배경

  • 명세7/23 Z8 사전예약 등록 시, CRM에서 삭제한 512GB 옵션이 플랫폼 BO로 다시 넘어감.
  • 명세현재 옵션 [삭제]는 실제로 is_use = 0 처리. 같은 통신사+용량으로 다시 등록하면 새 SN이 채번됨.
  • 명세그 결과 같은 상품이 SN 두 개로 존재 → 플랫폼·블링크 중복 노출, 판매 중단한 용량 재유입, CRM 상담의 옵션 참조 끊김("옵션을 다시 선택하세요").

1.2 목적

옵션 삭제를 없애고 옵션별 상태로 판매 여부를 관리하여, 한 번 등록된 통신사+용량 조합의 SN이 바뀌지 않도록 한다. 렌탈 '상품 부가 옵션'의 옵션항목 상태와 같은 구조로 맞춘다.

1.3 적용 범위

  • CRM Admin: 모바일 상품 등록·수정 화면 (기본정보 사용 여부, 용량/출고가 표)
  • CRM 상담: 상담상세의 모바일 상품·옵션 선택 목록, 저장된 상담 표시
  • 플랫폼(모바일 스쿼드): 상품 상태 + 옵션 상태 전달 (노출 판단은 플랫폼)
  • 데이터: 기존 판매 여부·옵션 is_use 이관, 같은 조합의 중복 SN 정리

3.3 SN · 등록 규칙

규칙내용근거
옵션 삭제 없음[삭제] 버튼 제거. 하드 딜리트도 하지 않음. 옵션이 한 번 저장되면 그 SN은 계속 점유명세
옵션 식별키 = 통신사 + 용량저장 후 통신사·용량은 수정 불가(고정 처리). 모델명·출고가·색상·옵션 상태는 수정 가능. 렌탈 부가옵션의 저장된 옵션항목명이 잠기는 것과 같은 방식해석
같은 조합 중복 등록 불가같은 기기 안에서 통신사+용량이 같은 옵션은 상태와 관계없이 새로 등록 불가 (품절·단종·숨김 포함). 저장 시점에 차단 (현재 동작 유지)명세
다시 판매할 때새로 등록하지 않고 기존 옵션의 상태를 판매중으로 변경 → 같은 SN 유지명세
잘못 등록한 경우통신사·용량을 잘못 고른 옵션은 숨김 처리 후, 올바른 조합으로 새 행 추가. 잘못 만든 조합은 점유된 채 남고, 나중에 필요하면 그 행을 판매중으로 전환해석
저장 전 행[+]로 추가하고 아직 저장하지 않은 행은 [취소]로 되돌림. 행 단위 제거 버튼은 두지 않음 (삭제 대체 버튼으로 오해 방지) — 필요 여부는 미정 9해석

3.4 CRM 상담 반영

구분규칙근거
상품·옵션 선택 목록상품 사용 AND 옵션 판매중인 것만 노출명세
저장된 상담 조회
(SN 기준)		상품·옵션 상태와 관계없이 그대로 표시하고, 현재 상태를 함께 표시명세
저장된 상담 수정·저장이미 선택된 옵션은 상태와 관계없이 유지·저장 가능. 필터는 새로 선택하는 목록에만 적용명세
목록 필터 기준 변경product_code.is_use 기준 → 새 상품 상태 + 옵션 상태 조합으로 변경해석

3.5 플랫폼 반영

구분규칙근거
전달 항목상품 상태(사용/미사용) + 옵션 상태(판매중/품절/단종/숨김) 모두 전달명세
노출 판단플랫폼이 두 값을 조합해 판단명세
합의 필요"상품 미사용이면 옵션 상태와 관계없이 미노출", 숨김·단종 처리 방식 → 플랫폼과 명시적 합의 (공유 예정)명세
중계 서버 인터페이스현재 isUse 단일 값 → 상품 상태 + 옵션 상태로 변경 필요해석

3.6 확장 정책 (Future Expansion)

CRM에도 상품 사용 상태 아래 옵션 상태를 나눠서 전달 → 판매중·품절·단종별로 상담상세 노출 방식을 다르게 처리 (렌탈처럼 품절·단종은 표시만 하고 선택 불가). 이번 범위 아님.
