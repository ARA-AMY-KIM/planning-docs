DESCRIPTION

㉮ /crm/internet/attributes?service=INTERNET&type=SPEED을 권합니다. 쿼리 없이 들어오면 인터넷 · 첫 번째 속성 타입이 기본입니다. 파라미터 이름은 type(속성 타입)입니다 — attribute는 이제 속성(1Gbps)을 가리키므로 쓰면 안 됩니다.

확인 필요 — internet 접두어가 남는 것이 걸립니다. 태그 관리도 구분 4종을 다 다루는데 경로는 /crm/internet/tags입니다(AS-IS 잔재). 새 화면에 그대로 답습할지 이번에 정리할지는 FE와 합의가 필요하고, ④ 상품 연결 관리도 같은 문제를 안고 있어 세 화면을 한 번에 정해야 합니다. PNB 도메인 분리로 /crm/ 접두어 자체가 바뀔 수 있는 것도 같이 봐야 합니다. 쿼리값은 한글이 아니라 코드값으로 둡니다.

변경 내용

breadcrumb을 「상품 관리」 1단계로 줄였습니다. 이전 안의 상품 관리 › 태그 관리 › 상품속성 관리는 이 화면이 태그 관리의 하위라는 뜻이 되는데, 실제로는 태그가 참조하는 상위 사전입니다. 구분 4종 공통이기도 해서 태그 관리 아래에 두면 계층이 거짓말이 됩니다.

툴바의 [태그 관리로] 버튼도 없앴습니다. 화면 간 이동은 GNB 하나로 통일합니다 — 화면마다 다른 복귀 버튼이 붙으면 어드민 전체의 이동 규칙이 깨집니다.

즉시 저장이라 이탈 확인 모달이 필요 없어졌습니다. 나갈 때 잃을 미저장 변경이 없습니다. beforeunload도 걸지 않습니다.

확인 필요 — 이 화면의 저장이 상품속성 캐시를 비웁니다. 태그 관리 탭을 따로 열어둔 채 여기서 속성을 고치면, 그 탭은 옛 속성 목록을 들고 있게 됩니다. GNB로만 오가면 매번 다시 조회되므로 대부분 해소되지만, 두 탭을 동시에 띄운 경우는 남습니다 — 태그 관리 쪽에서 속성 목록을 조회 시점 캐시로 쓰는지 확인이 필요합니다.

모달
속성 추가 · 이름 변경 · 삭제 확인
모달은 3개입니다. 추가·이름 변경은 입력 모달, 삭제는 확인 모달입니다. 이전 안의 저장 확인 · 이탈 확인 모달은 즉시 저장으로 바뀌면서 폐기됐습니다. 위 화면에서 직접 띄워볼 수 있습니다.
